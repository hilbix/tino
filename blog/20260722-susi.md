# Ausfall susi.de am Dienstag, 2026-07-21

## Zusammenfassung

- SUSI.de läuft als VM auf einem ProxMox-Host der viele weitere Dienste bereitstellt
- Bei Wartungsarbeiten auf dem Host meldete ZFS einen fatalen Fehler.
- Dadurch kam es zu einem ersten Crash von SUSI
- Eine Weile lang konnte die SUSI-VM wieder hochgefahren werden, aber dann kam es zum Crash aller VMs.
- Soweit bekannt kam es, abseits vom Ausfall selbst, zu keinem Datenverlust
- Das Dateisystem geriet dadurch in einen unrettbaren Zustand

# Zusätzliche Informationen und Gedanken

Der ProxMox-Host hat selbst keine Infrastruktur:

- Ich betreibe diesen ProxMox-Host privat auf meine eigenen privaten Kosten
  - SUSI zu monetarisieren widerspricht der SUSI-Philosophie
  - Spenden anzunehmen ist mir steuerrechtlich viel zu kompliziert
  - Ich werde zwar durch meinen Arbeitgeber etwas unterstützt, aber das ändert nichts
- Der ProxMox-Backup-Server wird nicht verwendet
  - Backups erfolgen auf Basis von ZFS
- Es gibt keine Redundanzen
  - Also auch kein HA-Setup
  - Solch ein Setup würde die Hostingkosten mehr als verdoppeln

Das bedeutet, das Recovery muss auf dem Host selbst geschehen.

- Genau dieses Szenario wird von ProxMox selbst nicht unterstützt.
- Das ist kein Fehler von ProxMox
  - Das ist eine Konsequenz aus der Art und Weise, wie ich ProxMox für mich einsetze
  - Ich weiß sehr genau, was ich tue und kann deshalb mit solchen "Herausforderungen" umgehen
  - Es braucht halt nur leider etwas länger wenn man Etwas das erste Mal machen muss

Weil ich dauernd mit irgendwelchen anderen Dingen beschäftigt bin (SUSI ist nur ein kleiner Teil, der größte Teil ist, als Arbeitnehmer Geld zu verdienen) bin ich leider bisher nicht dazu gekommen, das zu erstellen, was HilbiX sein soll:

- Ein Minitatur-Linux vor dem Linux
  - Der Kern muss in unter 250 MB passen
- Es muss flexibel sein:
  - Damit man es auch nachträglich installieren kann
  - Damit es genau die Arbeiten, die ich hier machen muss, ebenfalls möglich macht

Es muss einige Grundlagen bieten:

- Bootbar
  - von einer EFI-Partition (deshalb max. 250 MiB)
  - von einer Business-Card (diese haben als CD nur 50 MiB, gibt es die als DVD mit 250 MiB?)
  - von einem USB-Stick
  - via GRUB
  - via LoadLin oder ähnlich
- Besteht nur aus einem Kernel und der InitRD
  - Kann auf den jeweiligen Einsatzzweck leicht (per Web) zugeschnitten werden
- Sicherheit by Default
  - Secure Boot
  - Authentisierte Module
- Remote-Zugriff anywhere
  - Ermöglicht den sicheren externen Zugriff über Firewallgrenzen hinweg
- Fungiert als Pre-Boot-Environment
  - Zur Installation
  - Zur Maintainance
  - Zur Überwachung
  - Zur Gefahrenabwehr

Das hört sich kompliziert an, ist es aber eigentlich überhaupt nicht.

- Das Kernsystem soll ledglich anpassbar an den jeweiligen Fall booten.
- Es soll über Module flexibel erweiterbar sein, die man einbinden kann.
- Der Rest sind eigentlich nur die passende Bereitstellung vorhandener Bordmittel.

Und genau aus diesen Mitteln kann man dann solche Module selbst schnell bei Bedarf "zusammenbasteln".
